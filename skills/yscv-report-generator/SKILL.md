# 玉山保育志工回報單產生器（yscv-report-generator）

玉山國家公園的保育志工用圖形介面填寫回報單，程式把內容填進**固定的 Word 範本**，產生 `.docx`，再用 Microsoft Word 轉成同名 PDF。原始碼：Python 3 + Tkinter（桌面）。界面與說明一律使用**繁體中文**。

> 這份文件描述「行為與規則」，用來在別的平台（手機 app、網頁）重做時參考。Tkinter 畫面本身不需要照搬，但規則要保持一致，使用者才不會覺得是另一個程式。

## 1. 專案結構

| 檔案 | 內容 |
| --- | --- |
| `yscv_report_generator.py` | 主程式：保育巡查回報單、共用元件（照片、草稿、對話框、主題）、入口選單、意見反應、檢查更新的畫面 |
| `yscv_reports.py` | 塔塔加保育宣導回報單、生態廁所回報單（繼承巡查回報單的畫面） |
| `yscv_updates.py` | 檢查 GitHub 有沒有新版（只查詢，不下載） |
| `apps_script_feedback.gs` | 意見反應的 Google Apps Script 端點（程式 POST，Google 端寄信） |
| `保育巡查回報單.docx`、`塔塔加保育宣導回報單.docx`、`生態廁所回報單.docx` | 固定範本（著作權屬玉山國家公園，**不在 MIT 授權內**） |
| `build_exe.py`、`tools/make_manual.py` | PyInstaller 打包、產生 PDF 使用說明 |
| `tests/` | unittest（約 470 項）：產生 Word、畫面流程、安全、更新檢查 |

## 2. 三種回報單

入口選單（點選或按 1～3，Esc 離開）選擇其中一種。每種都有「基本資料」分頁與「照片」分頁，其他分頁不同。分頁標籤上的**橘色小圓點**表示該頁還有欄位沒填，填完變成**勾**（各主題顏色不同，見第 3 節；「服勤照片」裡的小分頁也一樣）。

### 2.1 保育巡查回報單（`patrol`）

- 基本資料：填表日期（民國年月日，**啟動時、按「清除所有資料」後、載入的草稿沒有日期時，自動帶入今天**）、協勤人員姓名（整段原樣寫進 Word，不拆分）、協勤日期（起～迄）、協勤地點。
- 文字分頁（每個欄位是多行輸入框，**下方有一條橫條可上下拖曳調整高度，2～40 行**；右上角有「項目符號/編號」下拉選單，可加上 ● ◆ ■ 或編號、再選一次取消）：
  - 道路/步道：道路步道狀況及維護情形、雜草情形、其他
  - 設施：山屋、牌示、木棧道、其他
  - 自然資源/環境維護/遊客管理：自然資源狀況、環境清理及遊客宣導情形、遊客違法情形
  - 遊客意見/心得建議/疑問解答：登山遊客反應意見、協勤心得與建議、相關疑問與解答
- 服勤照片：六個類別（道路步道、設施、自然資源、環境清理、遊客宣導與違法、其他），每張照片有一行說明。
- 在有項目符號或編號（`1.` `2.`…）的行按 Enter，會自動接上下一個符號（編號加 1）；空的項目再按 Enter 則結束清單。
- 範本裡「1.相關疑問？答：因為……。」的範例文字，產生時一律拿掉。

### 2.2 塔塔加保育宣導回報單（`tataka`）

- 基本資料：志工姓名、值勤日期（單日，年月日）、時間（例如 `09:00～16:00`）、天氣（晴／陰／雨）。注意**沒有「填表日期」與「起迄日期」**，Word 裡的日期就是值勤日期（和填表日期一樣，空白時自動帶入今天）。
- 服務項目：帶團解說（預約、散客兩個勾選）、塔塔加遊客中心（勾選＋文字，**填了文字自動打勾**）、其他（勾選＋文字）。
- 偶發事件：無／有；選「有」時逐筆記錄，可按「+」新增多筆。Word 裡只有一筆時寫在「有：」後面，多筆時在下面逐行編號（`1. 2. 3.`）。
- 設施與遊客意見：園區設施現況及改善意見、遊客意見。
- 心得與疑問解答：值勤心得、相關疑問與解答。
- 相片記錄：每張照片兩段說明——**名稱**和**詳細地點**（Word 裡左欄放文字、右欄放照片）。
- **志工姓名拆分**（`split_names`）：一定是分隔的符號有頓號、逗號（全半形）、分號、斜線、直線、換行。空白則依內容判斷：含漢字的詞各自是一個姓名；沒有漢字的詞（英文、韓文等外文）連在一起視為同一個姓名（`王小明 John Smith 李小華` 是三位）。多位外文姓名要用逗號隔開。報告裡**每位志工一行**。

### 2.3 生態廁所回報單（`ecotoilet`，玉山主峰線）

- 基本資料：填表日期、協勤人員姓名（整段原樣寫進 Word）、協勤日期（起～迄，**勤務是兩天：起日是有效日期時，迄日若是空白或還是上次自動帶入的值，就改成起日隔天**；使用者自己改過迄日就不再蓋掉；起日的年可輸入民國年或西元年，迄日跟著用同樣的年份表示）、協勤地點（**空白時帶入預設「孟祿亭、白木林生態廁所」**）。
- 兩座廁所各一個分頁（孟祿亭、白木林），每座有兩張記錄表：
  - （一）排泄物處理記錄：本次收集桶總量（kg）、天候（晴／雨）、汙泥桶清理（有／否）、取出不能腐化垃圾量（kg）、添加新腐植土入桶量（kg）、收集腐植土備用量（kg）、備註（選填）
  - （二）堆積場處理記錄：生態觀察、溼度處理、堆積溫度、異味處理添加量（kg）、翻堆（是／否）、備註（選填）
- 文字分頁：自然資源／環境清理（二、三）、協勤心得與建議（四）。
- 監測及維護照片：每張照片一行「照片文字」。

## 3. 共用的填表規則

- **民國年**：畫面與 Word 都用民國年（西元年 − 1911）。巡查與生態廁所會檢查填表日期、協勤日期（起）、協勤日期（迄）都是有效日期（以輸入的數字直接組成日期，所以年填 115 就是 115）、且**起日不可晚於迄日**；塔塔加檢查值勤日期。不通過就跳出錯誤（例如「「協勤日期（起）」不是有效的日期，請檢查」），不繼續產生。
- **產生前的檢查順序**：①日期檢查；②照片檔案是否都還存在（有不存在的就列出前 10 個並停止）；③**未填欄位檢查**：列出各分頁沒填的欄位與沒加照片的類別（備註欄除外）、另外提醒有幾張照片沒填說明，詢問「仍要產生報告嗎？」（預設「是」；選「否」會跳回第一個有問題的分頁）；④選存檔位置（輸出檔不能和範本是同一個檔案）。
- **內容拆行**：多行文字每行是一個段落（每行前後空白會去掉）；項目符號與編號由使用者在輸入框自己加，產生 Word 時程式不會再補。
- **XML 字元**：從 PDF 或網頁貼上的控制字元（空字元、垂直定位字元等）會在寫入 Word 前**自動移除**，不然 python-docx 會報錯。
- **預設值**：欄位是空的才自動帶入（填表日期、生態廁所的協勤地點）；已有內容（例如載入草稿）不蓋掉。
- 外觀主題三種：柔和淺色（預設）、色弱友善（避開紅綠，改用藍橘）、高對比；各主題的文字與背景對比度 ≥ 7:1（WCAG AAA，有測試檢查）。選擇會記在設定檔，立刻生效。
- **分頁標記**（主分頁與「服勤照片」的小分頁）：還有欄位沒填＝橘色小圓點、填完＝勾，畫成小圖放在分頁文字右邊（標籤前面本來就有圖示的分頁，例如生態廁所的廁所圖示，會把圖示與標記併成一張放在文字左邊，因為一個分頁只能放一張圖）。顏色依主題：柔和淺色＝橘黃圓點＋綠勾；**色弱友善＝橘色圓點＋藍色勾（不用綠色）**；高對比＝不用彩色圖，改用跟著分頁文字黑／白走的 `●` `✓` 符號（選取中的黑底分頁也看得見）。形狀（點與勾）本身就能分辨，不單靠顏色。
- 介面字型兩種：微軟正黑體（系統字型，**預設**）、芫荽（Iansui，隨程式附上，SIL OFL）。字型下拉選單**只放在入口選單的左下角**（和「檢查更新」「意見反應」同一排），選了**立刻重畫選單**（視窗位置不動、更新橫幅保留）並記在設定檔（鍵 `font`）；之後開啟的三種回報單在建立時讀同一個設定，所以版面（各分頁與視窗高度）一開始就依選好的字型量好，表單裡不再有字型選項（表單的「離開」會結束整個程式，在表單裡選字型也要重開才有用）。選的字型找不到時依序退回另一個字型、Arial。Word 報告的字型不受影響（一律標楷體）。
- **開啟回報單的版面與載入中遮罩**：視窗高度只量「最高的那一頁」（保育巡查是「設施」，塔塔加與生態廁所是照片頁），其他頁一定比它矮，所以不必逐頁量；量的時候要把該頁真的顯示出來（沒顯示時文字換行寬度會高估）。量的過程會閃過各分頁，所以先蓋一層「正在準備畫面，請稍候…」加不確定進度條的遮罩，量完、排好版再拿掉。欄位比較少的文字分頁（保育巡查的道路步道／自然資源／心得，塔塔加兩頁，生態廁所兩頁）讓多行文字框**往下長滿分頁**，不留空白，每個框至少比原本多 2 行。
- 入口選單底部一列：左邊字型下拉選單；右邊「檢查更新」「意見反應」；再下一列右邊是「啟動時檢查更新」勾選（左邊緣對齊「檢查更新」按鈕）加灰色版本。勾選框要等版面排好才算位置，換字型重畫後也一樣，否則會閃到最左邊。

## 4. 照片

### 4.1 操作

- 加入照片：按「加入照片」選檔（jpg、jpeg、png、gif、bmp），或從檔案總管把檔案／**資料夾拖進視窗**：非圖片檔略過並提示，已加入過的略過，一次拖多張依檔名自然排序（`IMG_2` 排在 `IMG_10` 前面）。拖進來時會切到照片分頁；**放在哪個小分頁標籤上就加到那一類（接在最後）**，放在清單某列上就安插在那個位置（列的上半部＝插前面、下半部＝插後面、表頭＝最前面），其他地方加到目前的類別最後面。新加入的照片會被選取。
- 點選清單中的照片會預覽；在預覽下方輸入說明，**Enter 儲存並跳到下一張**；在清單按 `N` 跳到下一張未填說明的照片。
- **拖曳調整順序**，也可拖到其他類別的小分頁（滑過標籤自動切換，顯示插入位置）。
- 預覽區：向左／向右轉 90°（不改原檔）、裁切（不改原檔，拖曳選範圍）；已裁切的照片檔名前標示 `✂`。
- Delete 移除所選照片；另有「移除所選照片」「移除全部照片」。
- 清單狀態：已填說明標 `✓`，未填說明標 `●` 並用淡橘底；檔名前標示 `(橫)` 或 `(直)`。

### 4.2 處理規則（`_load_photos`、`build_rows`、`plan_layout`）

1. 依 EXIF 轉正 → 使用者裁切 → 使用者旋轉（順時針，只有 0/90/180/270）。
2. 裁切範圍記成「**轉正後、未旋轉的原圖**」的比例（左、上、右、下，0～1），之後再旋轉也不會錯位；太小（寬或高 < 3%）或幾乎等於整張圖視為沒裁切。
3. 寬度超過 1200 px 就縮小，存成 JPEG 品質 85；不需處理時直接用原檔，不重新壓縮。
4. 版面（保育巡查）：**完全依使用者排的順序**，每列最多 2 張，**同一列必須同方向**（橫式與直式不並排；方向改變就另起一列，前一列可能只有 1 張）。橫式照片寬度一律填滿儲存格（每格寬度是頁面可用寬度的一半）；直式照片也以填滿寬度為原則，但過高時改以「高度上限」縮小（上限由頁高扣掉標題與說明、再除以 2 算出，讓兩列直式能排在同一頁）；照片一律放大到這個尺寸，不為了擠進頁面再縮小。模擬分頁：這頁放不下下一列就換頁。
5. 塔塔加：照片只有一類，**每張一列**（左欄是名稱與詳細地點兩行文字、右欄是照片，置中），高度上限 3 吋。生態廁所：照片也只有一類，**左右兩欄並排，每兩張一組（上圖下文字）**，不足的格子留白，高度上限 3 吋，不分橫直。
6. 照片載入失敗：Word 裡放「[照片無法載入：檔名]」文字，並在完成時警告「照片「檔名」無法載入：原因」，不中斷整份報告。
7. 圖片炸彈：保留 Pillow 的 `MAX_IMAGE_PIXELS` 保護，不能關掉。

## 5. 檔案命名（重要，改過）

- **報告**：`<協勤日期>_<地點>協勤回報單`（不放人員姓名）。日期用民國年：同一天 `1151015`、同月 `1150925-28`、跨月 `1150930-1002`。塔塔加是 `<日期>_塔塔加保育宣導回報單`；生態廁所地點已以「生態廁所」結尾就不重複加。
- **草稿**：`<日期>_<名稱>草稿_<全部人員姓名，以 _ 分隔>_<月日_時分>`，名稱依回報單：巡查是 `<地點>協勤回報單`（地點空白時用 `巡查回報單`）、塔塔加是 `塔塔加保育宣導回報單`、生態廁所是 `<地點>生態廁所回報單`。例如 `1151015_塔塔加保育宣導回報單草稿_王小明_李小華_1015_0930`。姓名依序全部列出（外文姓名保留中間的空白，例如 John Smith），總長度上限 120 字元（超過就只留放得下的前幾位，不切到姓名中間）。日期或姓名還沒填就略過那一段。
- 檔名會拿掉不能用的字元（`\ / : * ? " < > |` 與控制字元）。
- 存檔視窗預設資料夾：直接跑 .py 是程式資料夾，打包後是「文件」；產生報告存檔後會記住那個資料夾，之後報告與草稿的存檔視窗都從那裡開始（儲存、載入草稿本身不會更新它）。報告 `.docx` 與同名 `.pdf` 一起產生，產生後**自動開啟 Word 檔（不會開 PDF）**。

## 6. 草稿與自動存檔

- 草稿是 JSON：

```json
{
  "version": 1,
  "report": "patrol | tataka | ecotoilet",
  "saved_at": "2026-10-15T09:30:00",
  "fields": {"year": "115", "...": "單行欄位"},
  "texts": {"road_status": "多行欄位原始輸入"},
  "photos": {"類別": ["完整路徑", "..."]},
  "captions": {"類別": {"路徑": "說明"}},
  "rotations": {"類別": {"路徑": 90}},
  "crops": {"類別": {"路徑": [左, 上, 右, 下]}}
}
```

- 載入草稿的流程：選檔 → **先整份檢查**（`version` 必須等於 1；`report` 必須是目前這種回報單，沒有這個欄位視為巡查；各區塊必須是物件、`photos` 的值必須是清單）→ 通過後才問「載入草稿會覆蓋目前畫面上的內容，確定嗎？」→ 才動畫面。格式不對只顯示「無法載入草稿：原因」，不動目前畫面。
- 還原內容的規則：單行與多行欄位一律當文字；`captions` 只還原有內容的；`rotations` 只還原非 0 的角度（0/90/180/270）；`crops` 重新整理過，不合法或太小的丟掉；草稿裡不存在的類別略過；舊版分類名稱自動轉換（「環境清理及遊客宣導情形」→「環境清理情形」，「遊客違法情形」→「遊客宣導與違法情形」）；照片檔案已不存在就略過並提示「找不到照片，已略過：路徑」。載入後「填表日期」若草稿沒有就補上今天。
- **草稿可能來自別人**：照片路徑只接受本機完整路徑；網路路徑（`\\主機\分享`）、裝置路徑（`\\?\`、`\\.\`）、相對路徑、非字串、空字串、含空字元一律略過並提示，避免 Windows 對外送出登入雜湊。
- 自動存檔：每 30 秒檢查，**內容和上次存檔不同、不是空白（不算自動帶入的填表日期）、且和上次自動存檔不同**才寫檔（先寫暫存檔再原子替換），狀態列顯示「已自動存檔 時:分:秒」。三種回報單各存各的（`yscv_report_generator_autosave.json`、`yscv_tataka_autosave.json`、`yscv_ecotoilet_autosave.json`）。下次啟動發現自動存檔會詢問「發現上次未儲存的自動存檔（時間），要還原嗎？」；選「是」還原，選「否」刪除；自動存檔壞掉讀不了就直接刪除。關閉視窗時：沒有未存內容就直接離開並刪除自動存檔；有未存內容會問「是」（儲存草稿後離開，並刪除自動存檔）、「否」（不存直接離開，**保留**自動存檔，離開前補存最新內容，下次可還原；但畫面已是空白就不留）、「取消」（留在程式裡）。
- 「清除所有資料」會先警告無法復原。
- 快捷鍵：Ctrl+S 儲存草稿、Ctrl+L 載入草稿、Ctrl+G 產生報告。草稿存成 JSON（縮排 2、不跳脫中文，直接寫檔、失敗會跳出「草稿儲存失敗」），檔名建議見第 5 節。儲存草稿成功後會**刪除自動存檔**並視為已存；載入草稿後也視為已存。

## 7. 產生 Word 與 PDF

- **範本填寫**：用 python-docx 開範本。
  - 保育巡查：依標籤文字（例如「1、道路、步道狀況及維護情形：」）找到儲存格，把內容插在標題段落後面，格式為標楷體 12pt、固定行高 22pt；基本資料表第一欄加寬；基本資料用固定的列、欄位置（至少 4 列、第一列至少 3 欄）。範本更新時標籤文字要保持一致。
  - 塔塔加：依**表格位置**填寫（需要 10 列、4 欄；列索引從 0 起算：1 是志工／日期／時間／天氣，2～7 依序是服務項目、偶發事件、設施、遊客意見、心得、相關疑問，8 是照片標題列，9 是照片列的範本，每張照片複製一列）；打勾用 Wingdings 2 的方框符號；填空用底線；列高原本是「固定」的會改成「最小」，文字多時才不會被切掉。
  - 生態廁所：依**表格位置**填寫（需要 4 個表格：基本資料、排泄物記錄表、堆積場記錄表、照片；每座廁所在記錄表裡佔 4 列，最後一列填資料）。
  - 範本結構不符會丟出「模板格式錯誤」的明確訊息，不會寫出壞檔。
- **照片章節**：產生時新增表格，再搬到「九、服勤照片」標題後面；說明文字放在每張照片下方。
- **PDF**：呼叫 Word（PowerShell + COM，`ExportAsFixedFormat`），強制停用巨集（`AutomationSecurity = 3`）；沒有 Word 時仍產生 `.docx`，並提示 PDF 失敗的原因。**這是整個程式唯一必須有 Windows 與 Word 的部分**。
- 產生在背景執行緒，畫面顯示進度條；產生過程不凍結畫面。

## 8. 意見反應與更新檢查

- **意見反應**（入口選單右下角）：標題（≤100 字）、內容（≤5000 字）、聯絡 Email（選填）。以 HTTPS POST JSON 到 Google Apps Script，由 Google 端用部署者帳號寄信；程式裡沒有任何郵件帳號密碼，也不讀使用者的郵件程式。主旨 `[回報單產生器 <版本>] <標題>`；標題與 Email 過濾換行與控制字元；成功寄出後 30 秒內不能再寄（失敗不用等）；端點網址只接受 https，逾時 15 秒，寄送在背景執行緒（Ctrl+Enter 寄出）。POST 的 JSON 欄位：`subject`、`body`、`app`（程式名稱，當寄件人名稱）、`reply_to`（Email 格式正確才附）、`token`（有設才附）。內文最後附「聯絡 Email：…（沒填寫「（未填）」）」與程式名稱、版本。端點網址與選用的 TOKEN 放在 git 忽略的 `yscv_feedback_endpoint.py`；Apps Script 端會再過濾一次，並限制主旨 200 字、內文 10000 字、整個端點每分鐘最多 5 封、每小時最多 30 封（不分來源），TOKEN 不符回「未授權」。收件信箱只存在 Google 端。
- **檢查更新**：向 GitHub `releases/latest` 發一個 GET（不帶個人資料）；啟動時最多每週一次，可關閉（`--no-update-check` 或環境變數 `YSCV_NO_UPDATE_CHECK`）。只接受**版本號比現在新的正式發行**（草稿、預告版忽略，不會降版）；「前往下載」的網址由程式自己用 repo 名稱與 tag 組出來，不信任伺服器回傳的網址；更新說明當純文字顯示（`# 標題` 與 `**粗體**` 轉成樣式、其餘原樣），限制 4000 字，網路逾時 8 秒、回應上限 1 MB。檢查結果與「略過的版本」記在設定檔（鍵：`update_auto`、`update_last_check`、`update_latest_*`、`update_skipped`，外觀主題是 `theme`）；一週內再啟動不連網，直接用上次記下的新版資訊顯示提示。**程式不會自己下載或安裝任何東西**，由使用者決定（可「略過這個版本」）。私人 repo 查不到發行，會顯示「找不到已發行的版本」而不是「已是最新版」。
- 版本標籤：`<tag>.<tag 之後第幾個 commit>-<sha>`（剛好在 tag 上是 `v1.1-652f829`），灰色小字放在入口選單右下角；打包時烙進 .exe。

## 9. 安全規則（移植時務必保留）

1. 草稿與任何外部檔案都視為不可信（見第 6 節）；格式不對不能動到畫面或清掉目前內容。
2. 寄出前不信任呼叫端：標題、Email、內文再過濾一次並限制長度；Email 格式嚴格檢查（不接受逗號、分號、角括號、換行）。
3. 只連 https；轉址不可從 https 降級；所有連線都有逾時，檢查更新另有回應大小上限。
4. 只在資料夾有 `.git` 時才執行 git（避免執行到被植入的 `git.exe`）；PowerShell 用系統資料夾的完整路徑。
5. 圖片處理保留 Pillow 的炸彈保護。
6. 設定、自動存檔、記錄檔都是**明文**，內含姓名等資料，放在使用者自己的電腦（打包後在 `%LOCALAPPDATA%\yscv-report-generator`），不進版控、不上傳。記錄檔只有加 `-d`（`-D`、`--debug`）才產生。
7. 不要把真實姓名、信箱、端點網址、TOKEN 放進 repo 或歷史紀錄。

## 10. 移植到手機 app 或網頁版

**可以直接沿用（純規則，和平台無關）**

- 三種回報單的欄位、必填判斷、日期規則、民國年轉換、姓名拆分、兩天勤務自動帶入迄日。
- 照片排序、裁切（比例座標）、旋轉、每列最多 2 張且同方向的版面規則。
- 草稿 JSON 格式與檢查規則、檔名規則（第 5 節）。
- 意見反應的過濾與限制、更新檢查邏輯（網頁版不需要）。

**要重做的部分**

- **畫面**：Tkinter 換成對應平台的元件。手機版建議每個分頁一個畫面，照片用系統相簿選擇器與長按拖曳排序。
- **Word 產生**：目前依賴 python-docx 逐段改寫範本。網頁版可在伺服器端沿用 python-docx，或改用 docx 範本引擎；手機 app 通常需要伺服器端產生（或用 docx 函式庫自行填寫）。**範本欄位標籤要維持不變**。
- **轉 PDF**：Word COM 只有 Windows 可用。其他平台可用 LibreOffice（headless）、Gotenberg 之類的服務轉檔，字型要用標楷體或相容字型，版面才會和 Word 一致。
- **檔案與路徑**：照片路徑在 web／手機是 blob、URI 或雲端網址，草稿格式的 `photos` 要改成可攜的識別（例如檔案雜湊或上傳後的 ID），並保留「不載入外部網址」的安全原則。
- **自動存檔**：改用 localStorage／IndexedDB 或 app 本機儲存；同樣只在有變動時存、載入前先檢查格式。
- **隱私**：網頁版若在伺服器處理照片與姓名，要明確告知、限制保存時間；不要把真實志工資料放進測試、截圖或 repo。
- **範本授權**：範本屬玉山國家公園，公開散布前要確認可以公開；MIT 只涵蓋程式碼。

## 11. 使用者可見的文字（保持一致）

- 名稱：玉山保育志工回報單產生器（打包後的執行檔與資料夾同名）。
- 按鈕：載入草稿(L)、儲存草稿(S)、產生報告(G)、清除所有資料、離開(E)；照片：加入照片、移除所選照片、移除全部照片、裁切、向左轉 90°、向右轉 90°、跳到下一張未填說明（N）。
- 對話框一律用程式自己畫的版本（字級比一般介面大），不使用系統訊息視窗。
